## 环境选择

### A. 首选：从已审计CSV复现

在 `Project3/Analysis_codex/` 创建自己的环境，包里不包含原机器的虚拟环境。

```bash
python3 -m venv .venv
# macOS/Linux
.venv/bin/python -m pip install -r requirements_csv.txt
.venv/bin/python verify_project.py
```

Windows可使用 `.venv\Scripts\python.exe`。Python 3.10或更新版本是较方便的选择。封存时实际CSV环境为Python 3.9.6；具体安装版本见 `handoff_docs/environment_snapshot.txt`，不是要求其他平台逐个强行安装同一wheel。

### B. 从原始pickle重新审计

原pickle来自pandas 3序列化，旧pandas可能不能读取。原代码的 `requirements.txt` 为该阶段保留。建议另建环境，不要将CSV阶段环境直接升级后混用统计结果。是否能安装pandas 3取决于接收方Python和包源；若不可用，仍可用已有CSV完整复现后续分析。不要为“兼容”擅自改写原始pickle。

```bash
python3 analyze_hs300.py --input ../Data/沪深300 --output rerun/audit
```

## 推荐执行顺序

先做只读核对，再按需要选择复跑。多数脚本默认覆盖同名输出，应在解压副本中操作，或显式指定新输出目录。

```bash
# 数学约束和训练日期检查
.venv/bin/python verify_project.py

# 完整RMT和滚动回测：输出到新目录
.venv/bin/python rmt_analysis.py --returns tables/07_log_return_matrix.csv --output rerun/rmt --portfolio-assets 100 --training-days 504 --rebalance-days 21 --max-weight .05 --transaction-cost-bps 10

# 行业结构：使用已封存行业缓存，不用联网更新
.venv/bin/python industry_structure_analysis.py --returns tables/07_log_return_matrix.csv --metadata rmt_tables/13_stock_industry_raw.csv --output rerun/industry

# 以下脚本默认直接写回其固定结果目录，只在工作副本中运行
.venv/bin/python project_completion.py
.venv/bin/python revision_analysis.py
.venv/bin/python revision_enrich.py
.venv/bin/python revision_plot_modes.py
```

`project_completion.py`、`revision_analysis.py`等是独立补充脚本，固定读取项目根目录下已保存的基线结果。将 `rmt_analysis.py` 输出到 `rerun/` 并不会自动使这些脚本读取新回测。若需要传播新结果，先明确输入路径，避免把不同版本混成一套统计。

`revision_analysis.py` 末尾会尝试Yahoo指数查询；它此前没有取得足够数据。实际指数结果由 `revision_enrich.py` 读取封存的东方财富响应离线生成，不需要再次获取。若要完全离线重跑，可在工作副本中禁用末尾Yahoo尝试，其余计算不依赖网络。

## PPT编辑与跨机器问题

包中保留全部原始 `.mjs` 代码和当前PPT。PPT脚本使用 `@oai/artifact-tool` 及Codex presentations技能的校验工具，没有把这些运行时库复制进交接包。它们不是普通Python依赖。

原脚本中的 `SKILL`、`RUNTIME`、`RT` 是原机器的绝对路径。接收方Codex应先读取其当前 presentations 技能，再通过其运行时发现工具找到本机对应位置，修改工作副本中的常量和 `node_modules` 连接；不要原样复制路径，也不要通过猜测安装私有包。

构建脚本一般会重新导出同名文件，而最终校验器拒绝覆盖已有交付文件和校验记录。请先改成新的候选、输出和记录文件名。最新修订脚本还会导入34页原稿再施加改动，**不会读取当前48页PPT里后续的手工编辑**。

`restore_chart_workbooks.py` 为导入导出时丢失工作簿引用的处理代码，复制六个真实源工作簿及公式引用，没有伪造来源。原生成验证文件保留在 `validation_records/`，仅对应各自记录的旧SHA值。
